## 2. P0 — ломает данные или заявленный функционал

**B1. Переименование героини не доезжает до игры.**
```js

  return /(^|\u0001)prompts\u0001heroines\u0001[^\u0001]+(\u0001name)?$/
           .test(o.path.join("")) || o.path[0] === "picks";

```
Регексп ждёт разделитель `\u0001`, а `join("")` его не ставит. Первая ветка не срабатывает никогда → `syncNamesToGame()` не вызывается. Фикс — либо `path.join("\u0001")`, либо проверять по индексам:
```js

  (o.path[0] === "prompts" && o.path[1] === "heroines" && o.path[4] === "name"));
```
Рядом `dropBelow` использует `p.join("")` с префиксным сравнением `k.indexOf(pre) === 0` — там `["app","tag"]` окажется префиксом для `["app","tagDelete"]`.

**B2. Промпт длиннее 8000 символов невозможно сохранить.**
```js
var str = (max = 8e3) => v => typeof v === "string" && v.length <= max ? String(v) : void 0;
```
`clean()` слишком длинную строку отбрасывает → `value === undefined` → `patch()` бросает `400 "Invalid value for …"`. Длина в UI нигде не показана. Лечится clamp'ом и счётчиком символов:
```js

```

**B3. Числа вне диапазона отклоняются вместо clamp'а.** `num(lo, hi)` возвращает `undefined` при выходе за границы, а `numBox` для `pipeline.scene.width` не передаёт `min/max`. Набрал 5000 при `num(256, 4096)` → 400. То же для `cfg`, `steps`, `clipSkip`, `scale`.

**B5. `__proto__` — рассинхрон валидатора и `clean`.**
```js
if (k === "__proto__" || k === "constructor" || k === "prototype") continue;   // clean: выбрасывает
else if (node["*"] && id.test(String(seg))) node = node["*"];                  // validatorFor: принимает
```
Путь `["layer","prompts","__proto__"]` проходит валидацию, но `setAt()` делает `o["__proto__"] = value` — это **устанавливает прототип, а не свойство**. При перезагрузке ключ исчезнет. Плюс `JSON.parse` создаёт `__proto__` как обычное свойство, поэтому аддон с таким ключом поедет дальше через `merge()`/`getAt()` и вернёт прототип.

**B6. `undo()` уничтожает бэкап и не бэкапит текущее состояние.**
```js

  …

```
Состояние, из которого ушли, теряется навсегда. `changed.clear()` означает, что после undo другая вкладка может молча затереть правки.

**B7. `useSave()` пишет файл в обход `save()`.**

Ни бэкапа, ни `this.revision++`. Вызывается при каждой смене героини/слота (в т.ч. из `/bridge/api/active-heroine`) — значит клиентский `baseRevision` проходит проверку, которую не должен.

## 4. Безопасность

**B30. Модель доверия дырявая и внутренне противоречивая.**
```js
function localOrigin(origin) { if (!origin) return false; if (origin === "null") return true; … }
function allowedOrigin(req) { const o = req.headers.origin; if (!o) return true; if (localOrigin(o)) return true; … }
function trusted(req) {
  const o = req.headers.origin;
  if (!o) return !req.headers["sec-fetch-site"] || …;      // ← curl/любая локальная программа = доверенная
  try { const u = new URL(o); return u.host === req.headers.host || /^(localhost|127\.\d+…)$/i.test(u.hostname); }
  catch { return false; }                                   // ← Origin: "null" → 403, а allowedOrigin его пускает
}
```
Что из этого следует:

1. **`Origin: null` (file://, sandbox-iframe) пускают в `/api/*`, но не в `/bridge/api/*`** — `new URL("null")` бросает, и `trusted` возвращает `false`. Несогласованность: одна и та же страница может рисовать картинки, но не может открыть настройки.
2. **Запрос без `Origin` и без `Sec-Fetch-Site` — доверенный.** Любая локальная программа (`curl`, скрипт, другое приложение) меняет настройки, удаляет аддоны, восстанавливает бэкапы. При `--host 0.0.0.0` это уже не «локальная».
3. **Порт в проверке хоста не учитывается** (`u.hostname`), а `u.host === req.headers.host` — учитывает. Логика рвётся на страницах вида `http://localhost:3000`.
4. **`handleBridge` не отдаёт CORS-заголовки** — все ответы `send(res, 200, …)` без `corsOf(req)`. Поэтому клиент с другого origin получает ответ, который браузер отказывается читать, и предварительный `OPTIONS` для `PATCH` не проходит. То есть «доверенный» вызов из iframe/другого порта фактически не работает.
5. **Токена нет вообще.** Нет `--token`, нет nonce в URL меню. `--host 0.0.0.0` = полный доступ всем в сети.

Фикс: свести `allowedOrigin`/`trusted` в одну функцию, применять `corsOf` и в `handleBridge`, добавить `Sec-Fetch-Site` для мутирующих методов, и ввести токен: при старте генерировать 32-байтный hex в `wayward-bridge-data/token`, требовать его для `/bridge/api/*`, когда `host` не loopback, и подставлять в `menuUrl`.

**B31. `--host 0.0.0.0` в паре с алиасом на 8189** отдаёт наружу ещё и `/images/saved/` — то есть всю галерею.

**B32. `/bridge/api/game-dir`** принимает произвольный путь и дальше `game.serve()` читает оттуда файлы (read-only, так что ок).

Пути защищены корректно: `library.filePath`/`media.filePath` делают `path.resolve` + `startsWith(root + sep)`, `addons` идут через `path.basename`.
