Now, **the security section** deserves care:

```js
function localOrigin(origin) {
  if (!origin) return false;
  if (origin === "null") return true;
  try { return /^(localhost|127\.\d+\.\d+\.\d+|\[::1\])$/i.test(new URL(origin).hostname); } catch { return false; }
}
function allowedOrigin(req) {
  const origin = req.headers.origin;
  if (!origin) return true;
  if (localOrigin(origin)) return true;
  try { return new URL(origin).host === String(req.headers.host || ""); } catch { return false; }
}
function trusted(req) {
  const origin = req.headers.origin;
  if (!origin) return !req.headers["sec-fetch-site"] || req.headers["sec-fetch-site"] === "same-origin" || req.headers["sec-fetch-site"] === "none";
  try { const u = new URL(origin); return u.host === String(req.headers.host || "") || /^(localhost|127\.\d+\.\d+\.\d+|\[::1\])$/i.test(u.hostname); } catch { return false; }
}
```

Problems:
1. **`u.hostname` regex allows ANY port.** So a page at `http://127.0.0.1:3000` (a random dev server you run) is "trusted" for the bridge. More importantly, **`http://localhost:ANY`** — an attacker who can make your browser load a page from `localhost:someport`... they'd need to run something locally. Hmm, but the real vector: a malicious page at `http://localhost:3000` you happened to open (e.g. a local dev server hosting attacker HTML) gets full access. Reasonable.

2. **`Origin: null` → trusted.** Any page with `sandbox` (without allow-same-origin) or `file://` gets full access. A malicious site can embed `http://127.0.0.1:8788` in a sandboxed iframe and read/write everything (since `Origin: null` is allowed and the CORS header is echoed). Wait — for `trusted()` with `origin === "null"`: `new URL("null")` throws → `catch` → return false! Let me check: `trusted()` does `const u = new URL(origin)` where origin = "null" → `new URL("null")` throws (invalid URL) → returns false. So `Origin: null` is NOT trusted for `/bridge/api/*` → 403. But `allowedOrigin` → `localOrigin("null")` returns true → so `/api/*` allows it and echoes CORS. So there's an **inconsistency between `allowedOrigin` and `trusted`**: `Origin: null` can use `/api/*` (generate images, batch) but NOT `/bridge/api/*` (settings). That's a bug — a sandboxed iframe gets a 403 on settings.

Hmm, actually more relevant: does the game page ever have Origin null? No. But it's an inconsistency worth flagging.

Now **improvement proposals** — concrete:

1. **Fix the settings pipeline:**
   - `str()` → clamp instead of drop; add a `chars` counter in the UI; raise the prompt limit to 32k with a warning at 8k.
   - `num()` → clamp; wire min/max from SCHEMA into `numBox`.
   - `clean()` → return `{value, warnings}` or collect issues into a report shown as a toast.

2. **Fix `__proto__`:** use `Object.defineProperty` in `setAt` or skip those keys in `validatorFor`.

3. **Backups:**
   - unique backup names (`toISOString()` + `-` + counter or pid).
   - `useSave` → go through a common `persist(reason, {backup})`.
   - `undo()` → push the current state as a new backup before restoring.
   - keep a separate `changed` epoch instead of `clear()`.

4. **`writeAtomic`:** replace the busy-wait with `Atomics.wait` or just retry with a short `fs.sleep`-ish loop; add a unique tmp suffix; `fsync` before rename for durability.

5. **Security:**
   - add `--token` / auto-generated token written to `wayward-bridge-data/token`; require it for `/bridge/api/*` when `--host` is not loopback, or always accept it via `?t=`.
   - unify `allowedOrigin`/`trusted` into one function and apply `corsOf` to bridge responses.
   - treat `Origin: null` consistently.
   - check `Sec-Fetch-Site` for all mutating methods.
   - bind 127.0.0.1 by default (already) and warn when `--host 0.0.0.0` is used without a token.

6. **Perf:**
   - cache `updates.check` result per (hash, version, settings-revision) instead of per request.
   - split `/bridge/api/state` into `state` (full, once) + `state/light` (revision, jobs, diagnostics) for the 3 s poll.
   - `defaultLayer()` → build once per hash, then apply custom heroines into a *clone*.
   - `readAddon` once per add-on in `stateFor`.
